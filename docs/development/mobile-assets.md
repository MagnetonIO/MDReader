# Explicit native mobile images

The mobile reader can associate individually selected PNG/JPEG copies with an
exact imported Markdown revision. Original Markdown and selected image files
are not rewritten or deleted. No folder crawl or remote image fetch follows
from selecting a document.

## Ownership and flow

`src-tauri/src/mobile_assets/` separates IPC types, relative-target validation,
image validation, bounded read sessions and SQLite/file persistence. Its store
has separate schema, manifest, upload, read and cleanup modules.
`mobile_assets_commands.rs` is the thin mobile-only IPC adapter; expensive decode
and snapshot hashing run on blocking workers outside the embedded owner's lock.
The owner revalidates source/document/manifest authority before publication and
again while reading. Chunk reads check the original revision without repeatedly
parsing Markdown's image AST.

Only native Markdown AST image targets are selectable. Canonical relative paths
are decoded once, bounded and checked; absolute paths, traversal, schemes and
ambiguous percent remnants are rejected. Raw HTML image grants, SVG and animated
PNG are unsupported. The UI offers at most 64 targets and reports truncation.

## Resource bounds

| Boundary | Limit |
| --- | --- |
| Selected encoded PNG/JPEG | 4 MiB each |
| Dimensions | 4096 per side, 4 million pixels |
| Decoder allocation budget | 24 MiB library budget; allocator overhead is excluded |
| Decoded output | 16 million bytes |
| Document storage | 8 copies, 16 MiB including pending/retired copies |
| Library storage | 512 copies, 32 MiB including pending/retired copies |
| IPC chunk | 64 KiB |
| Native encoded snapshots | Two, at most 8 MiB total |
| Concurrent validation | One |
| UI image reads / retained Blob URLs | Two / two |

Read sessions expire after 15 seconds. Expired entries are swept on subsequent
read activity; explicit close, rejection, completion and app shutdown also release
resources. The UI closes late-opened sessions and revokes URLs on visibility,
manifest/revision changes and unmount. These are logical limits, not measured
WebView/process RSS guarantees or a hard CPU quota.

## Durability and cleanup

Private generated filenames are confined to the persisted asset-root identity.
Initial schema creation/additive prototype upgrade and version publication occur
in one SQLite transaction. Newer/unknown asset schema versions fail closed;
existing rows and private bytes are not reset. Ordered schema SQL lives beside
the owning store module.

Reservations commit before file creation. File appends are synced before their
received offset advances. Interrupted writes replay from zero against exact
previous bytes; incomplete/invalid copies never become readable assets. Full
PNG/JPEG decode is required before publication. A durable monotonic manifest
generation fences pending selections even after an intervening add/remove cycle.

Explicit removal retires authority before deleting the generated private copy.
Failed deletion retains a visible retired record and its quota for retry.
Sources inventory/forget works from bounded metadata even when the original
source has been revoked or the document changed; it cannot restore a grant or
remove an original. Lost replies are reconciled against inventory/manifest rather
than treated as proof of failure or success.

## Verification and remaining acceptance

The actual app's ten focused `mobile_assets::tests` pass, covering PNG/JPEG,
canonical paths, exact replay/reopen, quota/invalid images, ABA manifests,
revocation/root replacement, read-slot cleanup, inventory/forget, target
truncation and additive/future schema handling. The feature's isolated native
harness also passes strict all-target Clippy. This does not claim whole-legacy-app
strict Clippy acceptance.

The 13 mobile composition and 10 asset UI tests, app TypeScript check and scoped
ESLint pass. Actual command bindings are generated by the app test. For native
iteration, use the existing cache and the team's exclusive build slot:

```sh
CARGO_BUILD_JOBS=2 cargo test --locked -p mdreader-app --lib mobile_assets::tests -- --test-threads=1
```

Newest iOS/Android packaging and real file-picker/image/read/restart/visibility
acceptance remain open, including asset-root relocation after app replacement.
No latest device/GUI acceptance, sync projection, original-image export/share,
or production cloud deployment follows from these focused checks.
